# SiC Games — Audit Guide (the entry point for an auditor)

**Written 2026-10-26** at the supervisor's request, to let an auditor start productive work in the first hour.
It is a MAP: it states where each kind of fact lives and how to verify it. It does not restate findings; it points
to them. **Repo state at writing:** branch `r106/add105-malthus-churn` (RESULTS up to Addendum 114). Check
`git log -1` against the commit you were given.

---

## §0 How to use this guide, and how to classify a finding

**Reading order for the first two hours:** §1 (the project in one page) → **`docs/MODEL_STATE.md` (what works, what
meets its benchmarks, what does not)** → §2 (the canon) → the CURRENT SCORECARD at the top of `docs/MARKER_MATRIX.md` → §6 (known open items — do not re-report them as discoveries) → then pick lenses
from §8.

**Classify every finding as exactly one of** (carried over from the June guide, `SiC_Games_Fable_Audit_Guide.md` §0):
1. **INCONSISTENCY** — two parts of the repo contradict each other: spec vs code, doc vs run file, a value vs its
   cited source, a conclusion vs its own evidence. The most useful class.
2. **UNSUPPORTED CLAIM** — a value, mechanism or conclusion with no traceable backing (code, data, or a cited source
   that says it).
3. **DESIGN PREFERENCE** — internally consistent, but you would do it differently. Low priority; label it as such.

**Suggested mode:** read and run freely; write nothing in the tracked tree; put your report and scratch outputs
outside the repo (or in a git-ignored folder). A failing test or a bug is a finding to document, not to fix.

## §1 The project in one page

**What it is.** An agent-based model (Python 3.14, Mesa) of emergent social evolution. Agents live on climate-
generated terrain worlds (100 × 100 cells, 1 cell ≈ 100 km², 1 step = 1 month). They forage and hunt in kcal, store
food, form pair bonds and families, bands, villages and connubia, and develop status, material wealth, lineages and an
elite layer. Demography is explicit: a Siler mortality schedule modulated by terrain risk, density disease and
nutrition; energetic fertility; provisioning of children by mothers and fathers.

**History, in three phases.**
- **Phase 0 (June 2026, Stages 1–7.5):** two strategies, C (cooperative) and Si (individualist), on a Sugarscape
  grid; question H1(ii) — which is more resilient to shocks (RESULTS R-1). **Historical.** The C/Si comparison is not
  the current work, and the many `stage*.py` modules in the package belong to this phase.
- **Phase 1 (June–August 2026):** the terrain and resource ecology, then demography, Carbon status, climate, bands,
  settlements, agriculture and the elite layer (RESULTS R-2 … R-105; blueprints in `blueprints/phase1/` and at the repo
  root).
- **R-106 calibration arc (August–October 2026):** make the model reproduce the ethnographic record on three canonical
  worlds before any secular-cycles layer (RESULTS R-106 and its Addenda 1–114). The overarching goal stated by the
  supervisor: population must expand and spread while food lasts and contract on external shocks (Malthusian pressure).

**Where it stands** (MARKER_MATRIX, CURRENT SCORECARD; RESULTS Add.114): on the current canon every banded marker
passes on all three worlds, except two unresolved on temperate (#1 band size, #17 fission ceiling). The open threads
are listed in `docs/ROADMAP.md` → "CURRENT STATUS".

## §2 The canon: what a "canonical run" is

| question | answer | where |
|---|---|---|
| What does a canonical run execute? | The run file: every mechanism flag and every parameter, fully resolved | `config/runs/full_campaign.toml` |
| Where do those values come from? | The config classes (`DemographyConfig` etc.) via the canon builder `emergent_village_demog()` and `run_campaign.py`; `C_ALLON=1` switches on every built mechanism except the `_skip` set | `sic_games/outputs/phase1_social_evolution/run_se0_controlled_climate.py`; `sic_games/outputs/substrate_run/run_campaign.py` (`_skip`) |
| Generated config | `config/mechanisms.toml` (125 flags), `config/parameters.toml` (271 values), each with its provenance comment | `tools/gen_runconfig.py`; held in sync by `tests/test_runconfig_sync.py` |
| One table of every flag and parameter | canon state / value, class default, charter type, ladder tier, provenance tag, the field's own comment | `docs/REGISTRY.md` (GENERATED by `tools/gen_registry.py`) |
| Which flags are OFF in canon, and why | 27 of 125; each has its reason in `_skip` and in the field docstring | `run_campaign.py` `_skip`; REGISTRY §1 |

**Precedence** (docs/INDEX.md rule 6): code > `config/runs/full_campaign.toml` > generated `config/*.toml` > `docs/`.
A doc value that disagrees with the run file is a documentation defect. `py -3 tools/doc_audit.py --check params`
lists the disagreements (0 on 2026-10-26).

**Conventions that an auditor must know.**
- **Every mechanism is a flag, class default OFF, bit-exact when off.** The class default is for reproducibility of
  historical runs; the canonical stack is a separate question (root `CLAUDE.md`, "build it ON").
- **A magnitude travels with its flag** (R-85c): a flag switched on with a zero gain is not a live mechanism.
- **Adoption protocol (R-106).** A candidate is tested in "Stage 2": the real `run_campaign.py` pipeline, three
  canonical worlds (temperate = coastal/temperate, savanna = coastal/savanna, montane = mountainous/savanna), 15,000
  steps, the planet fixed (world and climate seed 0), three paired demographic seeds, a PERIOD life table over steps
  7,500–15,000, and a control re-run that must reproduce a stored canon run exactly. The supervisor decides adoption.
  **Known limitation:** until Add.114 the adoption runs scored only the targeted markers (see §6, item 3).

## §5 How to run and reproduce (from the repo root; Windows: `py -3`)

**Test suite** (15–50 min). The `--capture=sys` and `< NUL` are REQUIRED on Windows: five config test files start
subprocesses that fail intermittently with `WinError 6` under pytest's default capture (RESULTS Add.111):
```
cmd /c "py -3 -m pytest sic_games\tests -q --capture=sys < NUL"
```
Expected on 2026-10-26: all pass, 1 xfail.

**One canonical campaign:** `py -3 -u sic_games/outputs/substrate_run/run_campaign.py --config config/runs/full_campaign.toml`
(the run file's `[run]` section says 2,500 steps; the scored runs use 15,000).

**The runs behind the current scorecard** (Stage 2 of Add.113; ~7.5 h at 8 concurrent processes; temperate ~5 h each,
montane ~4 h, savanna ~2 h). Both adopted flags are now in canon, so the canon arm alone reproduces them:
```
set S2_CONC=8
set S2_ONLY_ARM=canon:
py -3 -u scratchpad/bp_stage2_driver.py
py -3 tools/scorecard.py --glob "campaign_trajectory_s2_*_canon_s*.json" --out <your scratch>/scorecard.json
```
Outputs go to `sic_games/outputs/substrate_run/` (git-ignored). The committed evidence to compare with is
`docs/evidence/scorecard_add113_canon.json` (made from the `riskvg` arm: `C_ALLON` + the two flags that were then
adopted; today's canon switches on the same flags through `C_ALLON`, so the runs are EXPECTED to be identical — not
yet verified by a run, and a good first check). Note: the canon-arm tag `_s2_<world>_canon_s<seed>` overwrites the
older Add.106 canon files of the same name. **A cheap
reproducibility check:** run one world and seed only (edit `S2_SEEDS` / the driver's `WORLDS`), then compare its
trajectory row by row with the evidence; the project's control re-runs have matched exactly every time.

**Documentation and anchors:**
```
py -3 tools/doc_audit.py            # paths, PARAMETERS vs run file, undocumented flags, freshness
py -3 tools/gen_registry.py --check # are REGISTRY / RESULTS_INDEX current?
py -3 tools/verify_anchor.py --list # the registered literature anchors (needs the PDFs, see §7)
```

## §6 Known open items — do not report these as new discoveries

You may report that a known item is WORSE than documented, or that its consequences are under-appreciated.
1. **Two markers unresolved on temperate:** #1 band size 40.2 ± 1.6 (≤ 40), #17 fission ceiling 232 ± 19 (≤ 250).
2. **The Add.113 result rests on one planet** (world/climate seed 0) with three demographic seeds; not replicated
   across world seeds.
3. **Adoption side effects found after the fact** (Add.114): the Add.113 adoption moved savanna #3-max 209 → 305,
   montane #11 0.195 → 0.241 (both report-only markers) and raised #15 orphanhood (savanna 0.017 → 0.029). Not
   diagnosed.
4. **#11 status→RS is NOT COMPARABLE** to its anchor (Add.102); **#5, #8, #9** are not computed by the scorecard.
5. **No cause-of-death marker;** starvation is 15–29% of deaths in canon.
5b. **The demography monitor fails on fertility and childhood:** TFR below the forager band on every world, m(5–15)
    2–3× Aché, montane IBI short, orphanhood high; and the monitor still scores band size with the statistic Add.89
    retracted (`band_med_adults`). `docs/MODEL_STATE.md` §3.
5c. **The spatial paradox flag is TRUE on every world** (packed locally, sparse regionally): the population does not
    disperse to its food. `docs/MODEL_STATE.md` §4.
6. **The Malthusian response** (spread, then contraction on a shock) is the arc's open goal; Add.105's "population at
   5–10% of carrying capacity" has not been re-measured on the current canon.
7. **Provenance debt:** 165 of 253 canonical parameters carry no provenance tag in their own source comment (REGISTRY
   §2); 12 flags have no comment of their own; two canon decisions have no recorded reason (`comove_footprint = 0`;
   `village_fission_threshold` 150 vs the 170 of PARAMETERS.md).
8. **Pinned blockers:** the band-cohesion budget has no headroom (Add.22, `test_cohesion_headroom.py`).
9. **96 broken file references** in live docs (70 in the append-only RESULTS) — listed by `tools/doc_audit.py`.
10. **Secular cycles:** four negatives (RESULTS Add.105 re-reads them); deferred.
11. The C/Si question (R-1, H1(ii)) is historical and not re-tested on the Phase-1 substrate.

## §8 Where defects have been found before — suggested audit lenses

Each lens names the defect class, one example from this project, and the check that would find a new instance.

| lens | example (record) | check |
|---|---|---|
| **Spec ≠ code** | the terrain-risk term scaled the whole a2, not the spec's 10% accident share, for two months (Add.112; filed in ae01ced, 2026-08-14) | read a MODEL_SPEC formula, then its implementation; `_a2_mult` per-factor observers |
| **Config drift** ("validated in one stack, dead in another") | `paternal_provision_frac` was 0.0 in canon against the documented 0.5 (Add.109) | REGISTRY `≠` column; compare a doc's "canonical" value with the run file |
| **Wrong statistic / unit / denominator** | #1 band size (median over band_id vs person-weighted per cell, Add.89); #14 (all-ages vs adults Gini, Add.90); l(45) from birth vs conditional (LITERATURE G&K note) | for each marker: statistic, unit, denominator and data freshness against the source (MARKER_MATRIX rules 2b, 5) |
| **A window is not a partition** | #17's 3×3 window straddled ~3 villages (Add.103) | any "largest local group" measure |
| **Instrument defects** | the CTB rule exists because instruments were wrong more often than the model (root CLAUDE.md; Add.31) | for any diagnostic a finding rests on: is there a `*_ctb.py` test with a constructed negative? |
| **Hidden denominator / validity domain** | thresholds on shares that fail silently when the denominator drifts (elite layer, R-91) | `invariants.py`; thresholds on ratios |
| **Seed variance** | e0 noise is dominated by the world draw; single-seed verdicts were reversed (MARKER_MATRIX rule 3; Add.76) | is the replication unit the right one for the marker? |
| **Adoption scope** | Add.113 was decided on #18–#21 only; side effects surfaced in Add.114 | does each adoption Stage 2 score the FULL marker table? |
| **Mis-attributed provenance** | `gen_runconfig.py` gives a field without its own comment a neighbour's block; 10 flags had another field's description (Add.114) | read a flag's comment at its definition, not in `config/*.toml` |
| **Bit-exact claims** | every flag claims "default OFF ⇒ bit-exact" | a control re-run with the flag off against a stored run |
| **Literature anchors** | four MARKER_MATRIX rows were once mis-attributed (Add.28); "savanna 31" had no source (Add.73) | `verify_anchor.py --list`; VERIFICATION_LOG; the cited page |
